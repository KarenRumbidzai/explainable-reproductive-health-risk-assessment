# Explainable Reproductive Health Risk Assessment

An explainable ensemble machine learning decision-support system for reproductive health risk assessment among women in Zimbabwe. Built for my BSc Honours in Business Intelligence and Data Analytics at Women's University in Africa.

The project uses dietary, environmental, lifestyle and reproductive-history factors to predict a Low, Moderate or High risk category, and explains each prediction in plain language.

> **Academic research prototype.** This is not a clinically validated diagnostic tool and must not replace professional medical advice.

## What's in the project

- **The model (KRM).** The Karen Rumbie Model is a stacked ensemble of Logistic Regression, Random Forest and XGBoost. It was developed and evaluated in a Jupyter notebook.
- **The app.** A Flask decision-support application. It takes a person's questionnaire answers, predicts their risk category, shows the factors behind the prediction and gives personalised suggestions.

## Dataset

- **Source:** a questionnaire collected through Google Forms.
- **Size:** 8,364 submissions, cleaned down to 4,300 genuine respondent records.
- **Split:** stratified 80:20, giving 3,440 training records and a held-out test set of 860.
- **Class balance:** 55% Low, 30% Moderate, 15% High, the same in both the training and test sets.
- **Variables:** age, province, urban or rural residence, diet (processed food, fruit and vegetables, legumes), physical activity, sleep, stress, BMI, environmental exposures (pesticides, air pollution, workplace chemicals), smoking, alcohol, and reproductive history.

**The dataset is not included in this repository, to protect participant privacy.**

## Method

1. Data cleaning, quality checks and exploratory analysis.
2. Feature engineering. The 19 questionnaire answers become 30 model features: ordinal encodings, yes/no flags, BMI category and province.
3. Stratified train-test split (seed 42).
4. Hyperparameter tuning with GridSearchCV and stratified 5-fold cross-validation.
5. A stacking ensemble: the three base models are combined by a meta-learner.
6. Evaluation with accuracy, macro-F1, macro ROC-AUC (one-vs-rest) and High-risk recall.
7. Explainability with SHAP.

## Results

Results on the held-out test set (n = 860):

| Model | Accuracy | Macro-F1 | ROC-AUC | High-risk recall |
|---|---:|---:|---:|---:|
| Logistic Regression | 0.731 | 0.695 | 0.872 | 0.659 |
| Random Forest | 0.684 | 0.617 | 0.855 | 0.488 |
| XGBoost | 0.721 | 0.679 | 0.867 | 0.597 |
| **KRM (stacked)** | **0.749** | **0.712** | **0.880** | **0.682** |

**What the results show:**

- **KRM scored best on every metric.** Its lead over Logistic Regression is small, though: about 1.7 points of accuracy and macro-F1. In repeated cross-validation the macro-F1 gap (about 0.005) was smaller than the variation between folds (about 0.012). The fair conclusion is that KRM is at least as good as the best single model, and slightly better.
- **Moderate is the hardest class to predict** (F1 ≈ 0.57). Low (F1 ≈ 0.85) and High (F1 ≈ 0.72) are much more reliable. Treat a Moderate result as borderline and look at the factors behind it.
- **Almost all errors fall between neighbouring classes.** Only 4 of the 860 test records were confused between Low and High.

**Reproducibility:** `app/models/model_manifest.json` records the seed, library versions and test metrics. The notebook was retrained from scratch on a second machine with a different operating system, and it reproduced every test metric to four decimal places.

## Explainability

For every prediction, the app:

- runs SHAP's `TreeExplainer` on the XGBoost model and shows the **five features that contributed most**, each marked as pushing towards or away from the predicted class;
- shows the probability of each risk category, so you can see when a result is a close call;
- gives up to four **plain-language suggestions**.

The suggestions are generated by rules based on the person's own answers, not from the SHAP values. So the link between the explanation and the advice is indirect, and no clinician has reviewed the wording.

## The Flask app

| Route | What it does |
|---|---|
| `/` | Redirects to the dashboard |
| `/dashboard` | Training-data context and statistics on registered members |
| `/predict` | Registers a member, then shows the KRM prediction, explanation and suggestions |
| `/members` | Browse and filter registered members |
| `/members.xlsx` | Download the member records as Excel |
| `/explore` | Upload any CSV or Excel file and get a quick exploratory summary |

**Storage:** SQLite by default (`sqlite_store.py`), with no setup needed. MySQL (`db_store.py`, `schema.sql`, `db_config.py`) and Excel (`data_store.py`) are included as drop-in alternatives. To switch, change the `import sqlite_store as data_store` line in `app.py`.

**Built with:** Flask 3.1, Jinja2, Chart.js 4.4, pandas, scikit-learn, XGBoost and SHAP.

## Running the app

### Requirements

- **Python 3.12.** The saved models only load under the exact scikit-learn (1.9.1) and XGBoost (3.4.1) versions they were trained with, and those are pinned in `requirements.txt`.

### Setup

```bash
git clone https://github.com/KarenRumbidzai/explainable-reproductive-health-risk-assessment.git
cd explainable-reproductive-health-risk-assessment/app

python3.12 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### Run

```bash
python app.py
```

Then open http://127.0.0.1:5050.

The dashboard's training-data panel needs the dataset at `app/data/reproductive_health_dataset.csv`, which isn't included. The rest of the app works without it.

### Tests

```bash
cd app
pytest
```

There are 47 tests: 18 unit, 20 integration and 9 system tests.

### The notebook

```bash
cd themodel
pip install -r requirements.txt
jupyter lab KRM_Notebook.ipynb
```

The notebook needs `krm_dataset.csv` in the same folder, and that file isn't included.

## Security notes

This is a local, single-user demo. Before deploying it anywhere:

- replace the hard-coded `SECRET_KEY` in `app.py`;
- set MySQL credentials through the `DB_HOST`, `DB_USER`, `DB_PASSWORD` and `DB_NAME` environment variables, instead of relying on the defaults in `db_config.py`;
- turn off `debug=True`.

## Limitations

- Predictions are not medical diagnoses, and the model has not been clinically validated.
- The model was trained on one sample of women in Zimbabwe, so performance may differ on other populations.
- Formal user acceptance testing was designed but not carried out.
- No clinician has reviewed the suggestions.
